Clerk Auth
+ College Hub

Replace the studio passphrase with Clerk, un-gate /major and /apply, and add a public /college hub reachable from the sidebar. One login, one owner, everything else public.

What exists today

  • Stack: Create React App (react-scripts 5) + react-router-dom v5, deployed to Vercel. api/*.mjs are Node-style serverless functions. Not Next.js.
  • /studio: real auth. bcrypt passphrase compare in api/auth/login.mjs, a jose HS256 JWT in an HttpOnly cookie named studio_session, verified by requireSession() in all five vault/exemplar routes.
  • /major and /apply: fake auth. GATE_PASS = 'go-fish' is a string literal in the shipped bundle, with a localStorage flag. The source comment already says "UI privacy only, not security."
  • Sidebar: src/pages/top_bar.js. Has a working dropdown pattern (Driving, SAT). Mounted on home, pull, 404, sat, driving. Not on major, apply, or studio.

Auth architecture

Client

Package is @clerk/react. Note two things that changed recently and contradict older tutorials: the package is no longer @clerk/clerk-react, and <SignedIn> / <SignedOut> are deprecated in favour of <Show when="signed-in">.

Under CRA the key is read from REACT_APP_CLERK_PUBLISHABLE_KEY automatically. It is not passed as a publishableKey prop.

ClerkProvider must sit inside <Router>, because router integration needs useHistory(). So Routes.js gains one small bridge component between Router and Switch:

const ClerkBridge = ({ children }) => {
  const history = useHistory();
  return (
    <ClerkProvider
      afterSignOutUrl="/college"
      routerPush={(to) => history.push(to)}
      routerReplace={(to) => history.replace(to)}
    >
      {children}
    </ClerkProvider>
  );
};

<RequireAuth> wraps the two /studio routes and has three states:

  • !isLoaded → cream placeholder matching the existing Suspense fallback. No flash of the sign-in screen for an already-signed-in user.
  • signed out → <Redirect to={`/sign-in?redirect=${path}`} />
  • signed in → render children

New route /sign-in (path matched loosely so Clerk's multi-step flow works) renders <SignIn /> with an appearance object mapping Clerk element keys to the navy/cream tokens. There is deliberately no /sign-up route.

Server

api/_lib/auth.mjs is rewritten but keeps the exact same export and signature — requireSession(req, res) → Promise<boolean> — so all five call sites (vault/list, vault/read, vault/save, vault/new-draft, exemplars/list) are not touched.

import { verifyToken } from "@clerk/backend";

// 1. read the __session cookie (Clerk's, replaces studio_session)
// 2. verifyToken(token, { secretKey: CLERK_SECRET_KEY,
//                         authorizedParties: [...] })  -> 401 on failure
// 3. payload.sub must be in CLERK_ALLOWED_USER_IDS  -> 403 otherwise

Why user-ID allowlist rather than email: no extra network round trip per API call, no custom session-claim configuration in the Clerk dashboard, and no fallback branch when that claim is missing. The trade-off is an opaque ID in an env var that must be updated if the account is ever recreated.

Bootstrap: the 403 response body includes the rejected userId. So the setup loop is: sign in → open /studio → read your ID off the error → paste into the env var. One round trip, no dashboard digging.

To confirm during implementation, not assumed: verifyToken's return shape. The docs show a try/catch example but type it as JwtReturnType, which is a { data, errors } object in newer releases. The installed package will be read before this is written, rather than guessing which one applies.

The /college hub

Hero, then three cards. Major and Apply are plain links. Studio carries a lock chip and, when signed out, routes to /sign-in.

Copy is left as visible placeholders. The headline and the three card descriptions are your words, not invented ones. They will render as obvious […] markers so nothing fake ships by accident.

Verification

Real browser, real vercel dev, per the project's E2E rule. react-scripts start cannot serve /api/*, so it cannot test this at all.

  1. Signed out, /college loads — hero and three cards render, no auth prompt.
  2. Signed out, /major and /apply load — no passphrase box, no localStorage flag needed. Confirms the go-fish gate is really gone.
  3. Signed out, /studio redirects — lands on /sign-in, not on a half-rendered desk.
  4. Signed out, API is closed — curl against /api/vault/list returns 401. This is the check that actually matters; the client gate is cosmetic.
  5. Sign in, wrong-ID case — before the allowlist is set, /api/vault/list returns 403 and the body contains the userId. This is both a test and the setup step.
  6. Sign in, allowlisted — vault loads, a file opens, an edit autosaves and produces a real commit.
  7. Sign out — returns to /college; /studio gates again.
  8. Sidebar — College entry navigates on click and expands on +, at desktop and mobile widths.
  9. Hygiene — yarn build clean, no new lint warnings, existing Jest suites (model.test.js, portfolio.test.js, seed.test.js, vaultModel.test.js) still pass.

Risks

  • CRA 5 + modern package exports. @clerk/react targets modern bundlers. webpack 5 should resolve it, but source-map warnings from node_modules are likely. Cosmetic if so; a real resolution failure would be a blocker and would change the approach.
  • Clerk appearance API drift. Theming maps to Clerk's internal element keys. A Clerk update can change them. Failure mode is ugly, not broken.
  • Cookie domain in local dev. The __session cookie must be present on localhost under vercel dev for the API check to pass. Verified in step 4 above, not assumed.
  • Sign-up must be disabled in the dashboard. Until it is, anyone can create an account. They still cannot read the vault (the allowlist blocks them) but they can reach the studio shell.

Out of scope

  • The /debt sidebar link is dead — it points at a route that does not exist in Routes.js, so it 404s. Pre-existing, unrelated to this work, flagged not fixed.
  • No changes to vault storage, the GitHub integration, or Supabase.

Your setup steps

  1. Create a Clerk application at dashboard.clerk.com. Pick email as the sign-in method.
  2. Turn sign-up off — Configure → Restrictions → set sign-up mode to restricted. This is the lock that matters most.
  3. Create your user manually — Users → Create user, with your email.
  4. Copy both keys from API Keys into .env.local and into Vercel project env.
  5. Add your production domain to the Clerk instance so cookies work on olivernguyen.com.
  6. Write the hub copy — headline plus three card descriptions.
