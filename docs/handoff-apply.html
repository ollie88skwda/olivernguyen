And Entangled

The whole /apply page has never been committed to git. An auth branch now depends on it, so neither can be pushed without the other. Separately, the Supabase tables behind /apply and /major are world-writable. Nothing has been pushed.

Read this first

The most urgent item has nothing to do with git. apply_decision and major_decision in Supabase have RLS enabled but with policies granting the anon role ALL commands, USING (true) WITH CHECK (true).

The anon key is committed in .env in a public GitHub repo and also ships in the JS bundle. So anyone can read, overwrite, or delete Oliver's entire college decision document today. Fix this first; it is independent of every other item here.

How to fix it

Recommended order. Steps 1 and 2 are independent and can be done in either order.

  1. Lock down Supabase. Replace the permissive policies on both tables. The pages talk to Supabase directly from the browser with the anon key, so there is no session to key off — the practical fix is to stop trusting anon and move these reads/writes behind an authenticated path, or scope the policies to a real Supabase auth user. As a stopgap that at least stops anonymous writes: 
    drop policy "anon can write apply_decision" on public.apply_decision;
drop policy "anon can write major_decision" on public.major_decision;
    Note this breaks saving on both pages until reads/writes are re-plumbed. Decide with Oliver before running it.
  2. Ask Oliver whether /apply may enter public git history. This is the decision the whole hand-off hangs on, and it is his to make, not yours. The live site already serves this data publicly, but git history is permanent and indexed. If the answer is no, the options are: make the repo private, or move the school data out of the bundle and behind an authenticated API.
  3. If yes — let Oliver commit his own work first. Do not fold it into the auth commits. 
    git checkout main            # a006049b
git add src/pages/apply src/styles/Apply.css src/styles/ApplyB.css \
        scripts/build-apply-seed.mjs
git commit -m "Add the /apply portfolio page"
git add src/pages/major/sections src/styles/theme.css
git rm src/pages/major/Tooltip.js
git commit -m "<Oliver's own message for his major/ edits>"
  4. Rebase the auth work on top. 
    git rebase --onto main a006049b clean-auth
    Expect conflicts in src/Routes.js and src/pages/major/index.js — those are the two files both parties edited. Resolve by keeping Oliver's content plus the auth changes described below.
  5. Verify before pushing. 
    CI=true npx react-scripts test          # expect 8 suites, 105 tests
npx -y yarn@1.22.22 build              # expect "Compiled successfully"
grep -ri "<the passphrase>" build/ ; git grep -i "<the passphrase>"   # both must be empty
git diff --name-only origin/main..HEAD | grep -E '^\.(next|playwright-mcp|vercel|lavish|agents|claude)/' # must be empty
  6. Delete the polluted branch. 
    git branch -D feat/split-auth-college-hub

Traps worth knowing

  • This is Create React App with react-router-dom v5, not Next.js and not v6. Use useHistory, <Redirect>, <Switch>. The Vercel project's framework preset says "Next.js" — that is stale and wrong.
  • Pass publishableKey to ClerkProvider explicitly. Clerk's docs say to let it read the env var; that auto-detection is Vite-oriented and silently fails under CRA — the provider mounts, injects no script, and isLoaded stays false forever with no error anywhere.
  • verifyToken from @clerk/backend v3 throws and resolves to the payload. It does not return { data, errors } — that is the internal verifyJwt.
  • vercel dev is required for anything touching /api/*. Run npm run dev:vercel; plain npm run dev is CRA only.
  • Never commit the passphrase or its bcrypt hash. The repo is public. The hash lives only in .env.local and Vercel env.

Do not do these

  • Do not git add -A at the repo root. That is exactly what caused this. .next/, .playwright-mcp/, .lavish/, .agents/, .claude/, .vercel/, .DS_Store and ~45 loose PNGs are all untracked and unignored. Consider adding a .gitignore for them as a separate commit.
  • Do not git reset --hard while untracked files are staged. It deletes them from disk. That happened here; recovery was only possible because they were still reachable in a commit object.
  • Do not push anything until Oliver has answered step 2.
  • Do not write the /college copy. The placeholders are deliberate.
